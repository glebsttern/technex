## 2026-10-20 — мобильное меню: панель «выезжала и уезжала» при каждом переходе
- Тип: MOBILE
- Где: `themes/technex/css/style.css`, тот же блок `@media (max-width: 820px)` в конце файла
  (компонент «меню», все 304 страницы)
- Было: до того как JS поставит `.is-burger`, `.nav` — обычное горизонтальное меню без
  `transform`. Вместе с классом приезжают сразу и `transform: translateX(100%)`, и
  `transition: transform 0.3s`, поэтому браузер проигрывает анимацию закрытия панели.
  Страница к этому моменту уже показана (`body.is-ready` снимает `opacity: 0`), и на
  каждом переходе по внутренней ссылке в узком окне видно, как панель меню выезжает
  справа и уезжает обратно. Поймано скринкастом: панель видна в кадрах с ~900 мс после
  клика.
- Стало: закрытое состояние задано заранее — `.mainmenu .nav { transform: translateX(100%);
  visibility: hidden }` и `.mainmenu .nav.is-open { transform: translateX(0); visibility:
  visible }` внутри того же медиазапроса. При добавлении `.is-burger` значение `transform`
  не меняется, анимировать нечего. Открытие и закрытие по кнопке анимируются как раньше.
- Зачем: дёрганье на каждом переходе, самый заметный дефект мобильной версии после
  неработающего меню.

## 2026-10-20 — шрифты: убран прыжок вёрстки после подгрузки шрифта
- Тип: MARKUP (правка темы и `<head>` всех страниц)
- Где: `themes/technex/css/style.css` — `@font-face` для Onder; ссылка на Google Fonts
  в `<head>` всех 304 HTML (правка скриптом, строка была одинаковой везде)
- Было: `font-display: swap` у Onder и `&display=swap` в ссылке на Manrope. Занавес
  `body.is-ready` снимается по готовности DOM, то есть до загрузки шрифтов, поэтому

- Стало: Onder — `font-display: block` (файл лежит на своём же сервере, приезжает быстро,

  около 100 мс, не успел — страница остаётся на запасном и **позже не перевёрстывается**;
  на следующих страницах шрифт берётся из кэша. Так внешний сервис не может ни подвесить
  текст, ни сдвинуть вёрстку.
- Зачем: убрать прыжок контента при каждом переходе.
- Проверено: переход между страницами в окне 500×860 — сдвиг контента 0 px (замеры
  положения заголовка и первого абзаца на 0 / 150 / 400 / 900 / 2000 мс). Первый заход с

  Замечание на будущее: Manrope тянется с внешнего домена; на проде его стоит положить

### 5. Номер больше не ложится на строку поиска
Было: на 375 низ полосы контактов 111 при верхе поиска 100 — 11 px наложения,
сам номер заходил в поле на 3 px. Распорка 100 при высоте шапки 112.
Причина: `measurePin()` вызывается сразу после `fit()`, то есть в момент, когда
переход из однополосного режима в двухполосный ещё проигрывается. У полосы
контактов анимируются высота и верхняя отбивка, и замер попадал в промежуточное
значение — недосчитывались ровно те 12 px отбивки.
Стало: на время замера JS вешает на шапку `is-measuring`, CSS по этому классу
снимает переходы у полосы, после принудительного рефлоу замер идёт по конечному
состоянию. Замер после правки: 899 — поиск со 117, полоса до 116; 375 — 112 и
111; 320 — 152 и 151; распорка везде равна высоте шапки.

### 7. Крановые баннеры — два узких режима
Макет: Figma «Technex», секция 802:2426 — кадры « Normal» 1202 (800:2393),
900 (800:2394), 720 (802:2414) и пара «Баннер / КРАН ОПОРНЫЙ» +
«КРАН ПОДВЕСНОЙ» (802:2435).
- **≤899.** Карточка остаётся серой и скруглённой, содержимое перестраивается:
  картинка во всю ширину сверху, под ней кнопка во всю ширину, заголовок
  переезжает на кнопку (отдельного заголовка нет). Стрелки листалки остаются.
  Пропорция слота под картинку из макета — 1129/369; `object-fit: cover`, потому
  что наши png сняты с запасом по вертикали (1280×672 и 1280×705) и в макете
  этот запас так же обрезан.
- **≤719.** Выводятся сразу оба крана, друг под другом, без скруглений, на
  белом, разделённые бордером — как баннер радиоуправления. Стрелки скрыты,
  дорожка листалки становится колонкой. `transform` у `.cranes__track` снят
  через `!important`: его пишет инлайном JS (`technexCranes.render`), иначе
  вторая карточка остаётся уведённой за край.
  Слот под картинку — 671/300 с `object-fit: contain`. Фиксированные 300 px из
  макета не взяты намеренно: на 375 карточка вдвое уже, и под краном оставалась
  бы полполосы пустоты.
- Кнопки во всех узких режимах одинаковые: во всю ширину карточки, чёрные,
  скругление 8, подпись акцидентным Onder по центру, 9 px в режиме ≤719.
  Для подписи в разметку добавлен второй ярлык (как у радиоуправления) — правка
  тела блока `block-block-contentb4b2bb14…` («Карусель главная»).

### 8. Ховеры мессенджеров фирменными цветами
Telegram `#2AABEE`, WhatsApp `#25D366`, Viber `#7360F2`. Значок — цельный SVG
(круг + белый глиф), перекрасить его из CSS нельзя: маска убрала бы глиф вместе
с кругом. Поэтому рядом положены три копии, где у круга (`<path id="Oval">`)
залит фирменный цвет, остальное не тронуто: `fig-telegram-hover.svg`,
`fig-whatsapp-hover.svg`, `fig-viber-hover.svg`. Прежнее приглушение
прозрачностью снято.

- Проверено замером и в браузере на 1440 / 1200 / 1100 / 1000 / 950 / 930 / 899 /
  800 / 719 / 375 / 320: переполнения страницы нет ни на одной ширине, десктопная
  раскладка баннеров не изменилась (1440 — серая карточка 326 px, пульт за обе
  границы, подпись «Подробно»).
