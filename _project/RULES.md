# Правила проекта «Технекс — мобильная версия»

Версия правил: 1.1 · зафиксировано 2026-10-20, дополнено 2026-10-21 (п. 5.1 — все наши
стили в `mobile.css`)

## 0. Структура папок

```
C:\Work\technex\
  old\        архив прежней среды (локальная вёрстка v1, её assets, partials, старые .md и правила).
              ЗАПРЕЩЕНО читать, искать по ней, листать её и использовать как источник.
              Только по явному отдельному запросу пользователя в текущем сообщении.
  snapshot\   слепок http://web.mydns.su от 2026-10-20. Эталонная «ветка».
              Неизменяемый. В работе не читается — только для сверки по прямой просьбе.
  new-site\   рабочая копия слепка. ВСЯ работа здесь. Здесь же лежат эти правила.
    _project\ служебные файлы проекта (правила, журнал, реестр компонентов, сервер, отчёты).
              Всё остальное в new-site — это зеркало сайта.
```

## 1. Правило неприкосновенности `old`

Папка `old` не читается никогда — ни целиком, ни по одному файлу, ни поиском. Не является
источником решений, стилей, текстов и структуры. Если кажется, что ответ есть в `old` —
нужно спросить пользователя, а не открывать.

## 2. Правило неприкосновенности `snapshot`

`snapshot` — честный слепок того, что реально отдаёт сервер: HTML не переписан, ссылки не
подменены, ничего не почищено. В него не пишем. Он нужен только затем, чтобы в любой момент
можно было показать diff «как было на сайте → как стало у нас».

## 3. Никаких улучшений

Переносим технологический уровень как есть. **Запрещено** без отдельного согласования:

- менять теги на «семантичные», переписывать структуру блоков;
- переименовывать или чистить CSS-классы (включая классы Drupal: `field--name-…`, `block-…`,
  `views-…`, `node-…`);
- выносить инлайн-стили, удалять `width=`/`align=`, `&nbsp;`, `<br>`, вёрстку таблицами;
- подключать препроцессоры, фреймворки, сборщики, CSS-ресеты, новые библиотеки;
- менять порядок подключения CSS/JS, удалять служебные CSS/JS ядра Drupal;
- менять URL-структуру, имена файлов и путей зеркала;
- оптимизировать/пережимать картинки, менять форматы.

Если старое решение выглядит плохо — это не повод его переписать. Повод — согласовать.

## 4. Десктоп не ломаем

Основная работа — мобильная версия. Поэтому:

- правки мобильной вёрстки живут **только внутри медиа-запросов** (`@media (max-width: …)`);
- существующие правила не переписываются — новые дописываются;
- если правка физически не может не задеть десктоп, она сначала проговаривается с пользователем,
  и только потом вносится, с отметкой в журнале.

## 5. Два разных класса правок

Каждая правка относится к одному из типов, и они не смешиваются в одном шаге:

| Тип | Что это | Куда ложится | Что делает программист |
|---|---|---|---|
| `MOBILE` | CSS под мобильный вьюпорт | `themes/technex/css/mobile.css` | подключает CSS |
| `CONTENT` | текст, заголовок, добавленный/убранный элемент | HTML страницы зеркала | правит контент в Drupal |
| `MARKUP` | изменение разметки шаблона (крайний случай) | HTML всех страниц типа | правит twig-шаблон темы |
| `BUG` | следствие миграции: битая картинка, 404, пустой блок | фиксируется в отчёте | правит данные/настройки |

### 5.1. Все наши стили живут в `mobile.css`

Зафиксировано 2026-10-21.

**Любая наша правка стилей пишется в `themes/technex/css/mobile.css`, а не в `style.css`.**
Дописывать в конец `style.css` — нельзя, даже «одну строчку». Смысл отдельного файла в том,
что программисту передаётся обозримый объём работ, который подключается одной строкой и так
же одной строкой отключается; как только правки начнут расползаться по `style.css`, этот
смысл теряется и придётся снова сверяться со слепком.

Правила файла:

- `mobile.css` подключается **только после** `style.css` — и в зеркале, и в теме Drupal
  (следующей строкой в `technex.libraries.yml`). Часть наших правил переопределяет
  существующие: `.mainmenu__actions` переводится с `display: contents` на флекс, заголовок
  баннера снимается с Onder, пересобирается сетка блоков направлений. При подключении раньше
  `style.css` шапка и баннеры поедут.
- Внутри файла две секции: «общие правки» (работают и на десктопе — шапка, ховеры) и
  «мобильные правки» (только внутри `@media (max-width: …)`). Правило 4 про десктоп
  действует по-прежнему: всё, что затрагивает десктоп, сначала проговаривается.
- Переопределять чужое правило — нормально, это и есть способ работы: наш файл идёт позже,
  поэтому выигрывает при равной специфичности. Повышать специфичность искусственно
  (`!important`, нагромождение селекторов) — только если иначе никак, и с комментарием зачем.
- Исключение одно: `font-display` у `@font-face "Onder"` правится прямо в `style.css` —
  это дескриптор `@font-face`, из другого файла его надёжно не переопределить. Такое место
  помечается комментарием на месте и перечисляется в шапке `mobile.css`.
- Если понадобится ещё одно подобное исключение — оно так же комментируется в `style.css`,
  добавляется в список в шапке `mobile.css` и отмечается в журнале. Список исключений должен
  быть полным: программист читает его, а не ищет правки сам.

## 6. Журнал правок обязателен

`_project/CHANGELOG.md`. На каждую правку: дата, тип из таблицы выше, файл и место, что было,
что стало, зачем. Журнал — это и есть ТЗ программисту. Правка без записи в журнале считается
несделанной.

## 7. Компоненты фиксируются один раз

`_project/COMPONENTS.md` — реестр повторяющихся блоков и типов страниц, с привязкой к вероятному
Drupal-шаблону. Правка компонента = правка во всех страницах этого типа, по списку из реестра,
одним шагом и одной записью в журнале. Поштучные расхождения между копиями одного компонента
недопустимы.

## 8. Порядок работы по мобилке

1. Главная (`index.html`).
2. Листинги разделов (`/uslugi`, `/remont`, `/izgotovlenie`, `/katalog-tovarov`, `/v-nalichii-na-sklade`).
3. Карточки услуг и оборудования (основная масса страниц).
4. Новости: листинг + карточка.
5. Служебные: поиск, формы, 403/404, пагинация.

На каждом экране цикл: показать, что именно поехало → согласовать → править → проверить
в 375×812 и в десктопе → записать в журнал.

## 9. Проверка на реальном рендере

Никакой приёмки «по коду». Каждая правка смотрится в браузере через локальный сервер:

```
node _project/serve.js 8080
```

Проверяются оба состояния: мобильный вьюпорт 375×812 и десктоп. Внешние ресурсы (Google Fonts
Manrope, Яндекс.Метрика, Яндекс.Карты, Google Maps, картинки с i.ibb.co) тянутся из интернета —
без сети страницы отрисуются без шрифта и карт, это не баг копии.

## 10. Один шаг — одно согласование

Работаем шагами. Шаг = один экран или один компонент. Перед каждым шагом — что собираюсь
сделать, после — что сделал и что проверил. Пачками «я тут всё поправил» не сдаём.
